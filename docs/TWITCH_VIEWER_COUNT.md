# Twitch の同時接続数(同接)を表示する

Twitch には視聴者数を返す無認証の公開 API がありません。ヘッダーに Twitch の同接を出すには、
dev.twitch.tv に自分用のアプリを1つ登録し、その **クライアントID / クライアントシークレット** を
アプリの設定に入れます。

登録したアプリは自分のアカウントに紐づくだけで、Twitch アカウントの連携やチャットの権限は不要です。
未設定でもチャットの受信・表示は普通に動きます（視聴者数が出ないだけ）。

同じ手順はアプリ内にもあります: **設定 → 認証情報 → Twitch → 「初回設定の手順」**（クリックで開きます）。

---

## 1. 二段階認証(2FA)を有効にする

Twitch アカウントに 2FA が入っていないと、開発者コンソールでアプリを登録できません。

1. <https://www.twitch.tv/settings/security> を開く
2. 「セキュリティ」セクションで二段階認証を設定する
3. 設定後、開発者コンソールを開いている場合はリロードする

これは Twitch 側の要件で、回避手段はありません。

## 2. アプリケーションを登録する

<https://dev.twitch.tv/console/apps> を開き、「アプリケーションを登録」を押します。

| 項目 | 入れる値 |
|---|---|
| 名前 | **全 Twitch アプリで一意**な名前。`fast-comment-<自分の名前>` など |
| OAuth リダイレクト URL | `http://localhost:3000` を入力して「追加」 |
| カテゴリー | 任意（Application Integration / Chat Bot など） |
| クライアントタイプ | **機密 (Confidential)** |

### 名前について

自分のアカウント内だけでなく、**他の開発者のアプリとも衝突します**。`fast-comment` のような
ありふれた名前は既に取られていることがあるので、その場合は接尾辞を足してください。

### リダイレクト URL について

**サーバーを立てる必要はありません。** 同接取得に使う client credentials フローが送るのは
`client_id` / `client_secret` / `grant_type` の3つだけで、`redirect_uri` は送りません。
Twitch 側もこのフローでリダイレクト先へアクセスしません。

にもかかわらず入力するのは、登録フォームの必須項目だからです。公式ドキュメントの
client credentials の例でもこの値が使われているので、そのまま `http://localhost:3000` で構いません。
（`http://` が許されるのは localhost だけです。外部ホストなら `https://` が必要）

### クライアントタイプについて

⚠ **ここを間違えると作り直しになります。**

- **機密 (Confidential)** — シークレットを発行できる。同接取得にはこちら
- **公開 (Public)** — 仕様上シークレットを持てず、「新しい秘密鍵」ボタンが出ない

**登録後にクライアントタイプを変更できないことがあります。** 公開で作ってしまった場合は、
アプリを削除して機密で登録し直してください（削除直後は同じ名前を再取得できないことがあるので、
名前を少し変えるのが確実です）。

## 3. クライアントIDとシークレットを取得する

登録すると一覧に並ぶので、対象アプリの **管理** を押します。

- **クライアントID** — 32文字の英数字。管理画面でいつでも確認できます。秘密情報ではありません
- **クライアントシークレット** — **「新しい秘密鍵」** ボタンで生成します

⚠ **シークレットは生成した画面でしか表示されません。** その場でコピーして安全な場所に控えてください。
公式に再表示の手段はなく、失った場合は再生成することになります。再生成すると**古いシークレットは
即座に無効**になり、更新するまで同接の取得が失敗します。

## 4. アプリに設定する

fast-comment の **設定 → 認証情報 → Twitch** を開き、

- 「Twitch クライアントID」
- 「Twitch クライアントシークレット」

に貼り付けて保存します。

保存すると Twitch チャンネルが自動的に接続し直され、20秒間隔で視聴者数の取得が始まります。

---

## 動作と制限

- **配信中のチャンネルだけ数字が出ます。** オフラインのときは Helix が空を返すので `—` になります
- ポーリング間隔は 20 秒です
- チャット送信用の「Twitch OAuth トークン」とは別物です。両方設定されている場合は
  クライアントID / シークレット側を優先します（アプリトークンは期限切れを自動更新できるため）
- App Access Token はリフレッシュできない仕様なので、期限の 60 秒前に取り直します。
  Helix が 401/403 を返したときも1回だけ取り直してリトライします

## トラブルシュート

| 症状 | 原因と対処 |
|---|---|
| 「新しい秘密鍵」ボタンが無い | クライアントタイプが「公開」。機密で登録し直す |
| アプリを登録できない | 2FA が未設定。有効化してコンソールをリロード |
| 名前が弾かれる | 他の開発者のアプリと衝突している。接尾辞を足す |
| 保存しても同接が出ない | そのチャンネルが配信していない。配信中か確認する |
| 急に取得できなくなった | シークレットを再生成すると旧シークレットは無効になる。新しい値を設定し直す |

## セキュリティ

クライアントシークレットは、他の認証情報と同様に**この PC の `config.json` に平文で保存されます**。
共有 PC では取り扱いに注意してください。

シークレットはパスワードと同等に扱い、他人に共有しないでください。設定のエクスポート機能で
書き出したファイルにも含まれます。
