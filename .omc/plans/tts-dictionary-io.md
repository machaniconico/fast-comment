# 読み上げ辞書の入出力(2026-11-25、ルート決定。R2。URL の取得を含むので、レビューでは安全面を重く見る)

前提:
- 規約は `.claude/CLAUDE.md`。仕様は `.claude/SPEC.md` の §6(TTS)と §8.1(ポータビリティ)。
- 辞書は `config.json` の `tts.options.dictionary`(`Vec<TtsDictEntry{from,to,regex}>`、config.rs:641-650、756)。
- 辞書の適用は `tts/mod.rs` の 441-480 行。

## 決めたこと

### 形式
```json
{ "schema": "fast-comment-tts-dictionary", "version": 1, "entries": [ { "from": "...", "to": "...", "regex": false } ] }
```
- version が 1 以外なら拒否する。
- 未知のフィールドは無視する。
- `entries` の各項目は、ほかのアプリ向けの表現の揺れも受け入れる。
  - `from` の別名: `pattern`、`word`、`key`
  - `to` の別名: `reading`、`replace`、`value`
  - `regex` の別名: `isRegex`
- JSON の最上位が配列だけでも受け入れる。その場合は entries として扱う。

### 検証(Rust 側で一括して行う)
検証は Rust の新しい IPC で行い、UI は結果を表示するだけにする。
- 件数は 1000 件まで。超えたら拒否し、その旨をエラーにする。
- `from` は trim した後に 1〜200 文字、`to` は 0〜200 文字(chars で数える)。
- 正規表現は `RegexBuilder` の `size_limit(1 MiB)` と `dfa_size_limit(1 MiB)` でコンパイルして確かめる。不正な項目は、その行だけを捨てて理由を数える。全体は止めない。
- 結果として返すもの: `{ added, replaced, skippedDuplicate, rejected: [{index, reason}](最大 20 件), total }`。

### 取り込みの方式(UI で選ぶ)
- 「追加」(既定): 既存の辞書の後ろに足す。`(from, regex)` が既存と同じ行は既存を優先してスキップし、数える。
- 「置き換え」: 確認ダイアログを出し、辞書を丸ごと入れ替える。
- 取り込んだ後の辞書全体にも、件数の上限を当てる。
- 手で編集した config.json も守るため、`TtsOptions::normalize` にも同じ上限を入れる。超えた分は捨て、warn ログを出す。

### 取得元
- ファイル(UI のファイル選択)
- 貼り付け(テキスト欄)
- URL(Rust 側で取得する)

### URL 取得の制限
- `https://` だけを受け付ける。
- 接続先がループバック、プライベート、リンクローカル、CGNAT、マルチキャスト、未指定のアドレス(IPv4 と IPv6、IPv4 射影も含む)なら拒否する。名前を DNS で解決した後の IP で判定する。接続は判定した IP に固定する(reqwest の `resolve` を使う)。
- リダイレクトは最大 3 回。毎回、上と同じ検証をやり直す。
- タイムアウトは全体で 10 秒。
- 本文は 256 KiB までとし、ストリームで数えながら打ち切る。
- `Content-Type` は問わない。中身を JSON として読めなければエラーにする。
- エラー文には URL のクエリを出さない。ホスト名までは出してよい。
- URL 取得の IPC は UI(main ウィンドウ)からしか呼べないようにする。ローカル API と Webhook からは呼べないこと。

### 書き出し
- 今の辞書を上の形式で書き出す。保存の仕方は既存の Portability の部品と同じ(ダウンロードとクリップボード)。

### UI
- `Settings.svelte` の「読み上げ辞書」(`.dict-editor`、2443 行付近)のすぐ下に、`TtsDictionaryPortability.svelte` を置く。
- 置くもの: 書き出し、ファイルから取り込み、貼り付けて取り込み、URL から取り込み、追加と置き換えの選択。
- 結果は件数で表示する。拒否した行は、何行目か、理由をまとめて出す。

## 受け入れ基準(テスト)
### Rust の単体テスト
- 形式の読み込み: 正しい形、配列だけの形、別名、未知の version を拒否すること、未知のフィールドを無視すること。
- 件数の上限(1000 / 1001)、文字数の境界(200 / 201、全角と絵文字)、不正な正規表現はその行だけ拒否されること、巨大な正規表現が size_limit で拒否されること。
- 追加の時の重複スキップと置き換え、取り込んだ後の合計の上限。
- URL 検証: http を拒否、127.0.0.1・10.x・192.168.x・169.254.x・::1・fc00::/7・::ffff:127.0.0.1 を拒否、名前の解決先がプライベートなら拒否、リダイレクト先がプライベートなら拒否、4 回目のリダイレクトを拒否、256 KiB を超えたら打ち切り、タイムアウト。
  - ローカルのモックで確かめるために、検証の判定関数(IP の判定)を切り出して単体でテストする。取得の部分は、テストでだけ判定を外す口を設けてよい。本番のビルドでは外せないこと。
- エラー文に URL のクエリが出ないこと。
- `TtsOptions::normalize` の上限。
